A university library wants a simple system for borrowing books. Each member has a unique member ID. Each book has a title, and the library may have several physical copies of the same book. Every physical copy has its own copy ID and availability. A member requests to borrow a particular book copy. For this exercise, a member may have only one current loan at a time, and a physical copy may have only one active borrower at a time. The system checks whether the member already has a current loan and whether the requested copy is available. If the member has no current loan and the copy is available, the system accepts the request. It creates a loan record containing the member, the book copy, the borrowing date, the due date and an ACTIVE status. The copy becomes unavailable, and the member’s current loan refers to the new record. If either check fails, the system rejects the request. It creates no new loan and leaves the existing information unchanged. For example, member M01 requests COPY-01 of Java Basics. M01 has no current loan, and COPY-01 is available, so borrowing succeeds. COPY-01 becomes unavailable, and M01 receives an active loan. If member M02 then requests COPY-01, the request fails because the copy is already borrowed. For now, the system handles borrowing and rejected requests. Returning books and storing previous loans will be added later.
